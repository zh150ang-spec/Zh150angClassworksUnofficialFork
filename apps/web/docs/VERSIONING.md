# Classworks 版本号规范

本项目采用 **语义化版本控制 2.0.0**（Semantic Versioning，简称 SemVer）作为版本号管理规范。

## 版本号格式

```
MAJOR.MINOR.PATCH[-prerelease][+build]
```

- **MAJOR（主版本号）**：进行不兼容的 API、数据格式或用户界面重大变更时递增。对于 Classworks 而言，例如作业板数据模型发生破坏性变更、共享链接格式不再向下兼容、主要交互范式重构等。

- **MINOR（次版本号）**：向下兼容地新增功能或进行较大改进时递增。例如新增科目管理、新增数据同步模式、新增 PWA 能力等。

- **PATCH（修订号）**：向下兼容地修复问题或进行小优化时递增。例如修复同步冲突、修复布局异常、修复离线队列问题等。

- **prerelease（预发布标识，可选）**：用于正式版发布前的开发或测试版本，例如：

  - `-dev`：日常开发构建，可能不稳定。

  - `-alpha`：内部测试版本，功能和接口仍可能大幅调整。

  - `-beta`：公开测试版本，核心功能基本稳定，但可能仍有已知问题。

  - `-rc`（Release Candidate）：发布候选版本，如无重大问题即发布为正式版。

- **build（构建元数据，可选）**：在某些 CI/CD 场景下用于附加构建信息，例如 `+20250727`、 `+g1234567`。该部分不影响版本优先级比较。

## 版本号递增规则

1. 修复 bug 或进行不新增功能的优化：`PATCH + 1`。
2. 新增向下兼容的功能：`MINOR + 1`，并将 `PATCH` 归零。
3. 进行不兼容的变更或产品进入全新阶段：`MAJOR + 1`，并将 `MINOR` 和 `PATCH` 归零。
4. 预发布版本在对应正式版数字前追加标识，例如 `1.2.0-beta.1`、`1.2.0-beta.2`，直至最终发布 `1.2.0`。
5. 在 `0.x.x` 阶段，项目视为尚未达到稳定版，允许在 MINOR 版本中包含可能不兼容的变更。

## 当前版本号含义

当前版本号为正式版，采用 `0.13.0`：

- `0` 表示项目仍处于快速迭代期，尚未对外承诺稳定接口。

- `13` 表示完成 monorepo 迁移、工程底盘重构与公开 Fork 整理后的新次版本；本轮以项目结构统一与工程治理为主。

- `0` 表示新增同类向下兼容的功能改进，进入新的次版本迭代周期。

- 无预发布标识（`-beta`）表示本版本标记为可对外使用的正式发布节点。

## 版本号在仓库中的使用位置

- `package.json` 中的 `version` 字段是权威版本号来源。

- Service Worker 的缓存版本应与 `package.json` 的版本保持联动，确保版本更新后用户端缓存能够及时刷新。

- 关于页面等展示位置应读取 `package.json` 中的版本号，避免硬编码。

- 每次准备发布时，应在更新 `package.json` 版本号后同步更新本文件中的“当前版本号”说明，必要时补充 `CHANGELOG.md`。
