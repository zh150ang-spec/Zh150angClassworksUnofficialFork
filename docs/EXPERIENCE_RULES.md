# 经验规则

> 以下规则来自实际项目中出现的错误与卡顿，属于"血泪教训"。仅在涉及**子 Agent 协作 / 样式根因 / 跨组件改动流程**时，由主 Agent 主动遵循本文件。一般性任务无需反复阅读。

## A. 子 Agent 协作纪律

1. **子 Agent 的报告不可全信。** 曾多次出现子 Agent 报告"已修改完成"，实际文件未落盘（如按钮仍为 tonal、颜色未改）。凡子 Agent 交付，**必须重读文件核对落盘**，不得只依赖其文字报告。
2. **派发任务时文件必须互不重叠。** 并发修改同一文件会互相覆盖（StudentListCard 曾被多个 Agent 先后读写导致改动丢失）。给每个 Agent 分配互斥的文件白名单。
3. **子 Agent 的 prompt 必须内置强制验收**：逐文件列出改动点、末尾声明"已重读 {文件} 确认落盘"、`pnpm lint` 必须 exit 0 并汇报退出码。
4. **明确"只许修改以下文件，其余一律不动"。** 子 Agent 可能越界改动（曾顺手删除其他文件中的孤立标签）。越界即违规，需在 prompt 中明文禁止。

### 子 Agent 任务 prompt 参考模板

派发子 Agent 时，按以下骨架编写 prompt（示例节选自设置界面统一按钮样式的实际任务）：

```
修改任务：{一句话描述目标}
项目背景：Vue3 + Vuetify4 纯前端 PWA，路径别名 @/ → src/，图标一律用 @/utils/icons.js 的 ICON 对象，禁止裸写 mdi-。
只允许修改这些文件（严禁碰其他文件）：
- {文件清单，互不重叠}

【统一契约】
- {必做规则，如：带文字操作按钮 variant="elevated"、默认尺寸、:prepend-icon、语义色 success/error/warning/primary + 中性色 neutral-surface}
- {不要动什么：纯图标微按钮保持 small/text、表单控件/提醒组件不动}

【验收与严防遗漏】
1. 每个文件改完后【重新 Read 该文件】逐行确认改动真正落盘。
2. 在项目根目录运行 `pnpm lint`，必须 exit 0、无 ESLint 错误。
3. 不得删除/改动任何现有功能逻辑。

【强制报告格式】（缺一不可，严禁只说"完成"）
1. 逐文件逐改动点：旧→新 一句话。
2. 每文件末尾写一句"已重读 {文件名} 确认所有改动落盘"。
3. lint 结果：退出码 + 有无报错。
```

## B. 样式根因

1. **中性按钮颜色统一用主题 token** **`neutral-surface`**（在 `src/plugins/vuetify.js` 中按 dark/light 分别定义，dark=`#46464D`、light=`#E2E2E7`）。不要使用 `surface-container-*`（深色主题下与背景对比度不足）。
2. **全项目禁用** **`v-btn-toggle`** **分段切换控件。** 互斥单选一律改用 `v-radio-group` 等常规表单单选控件（正常项目不用分段切换）；主题"明亮/暗黑"切换保留一处（ThemeSettingsCard）作为例外。

## C. 改动流程

1. **改动前先 grep 全项目确认影响面。** 切勿只搜索局部目录（v-btn-toggle 全项目实际有 27 处，不止设置页）。
2. **同一类交互应收敛为可复用外壳 / composable**（如 SettingsCard 外壳、useConfigDefaults 兜底），不散落复制粘贴。
3. **大改动前先使用 AskUserQuestion 锁定范围与决策**，再派发子 Agent，避免半途返工。

## D. 交互工业级

1. 破坏性操作二次确认补全、耗时操作 loading/disabled 补全、裸 `mdi-` 字符串与硬编码颜色扫描修复。
